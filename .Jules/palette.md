## 2025-02-28 - Form Validation Persistence and ARIA Synchronization
**Learning:** Form validation errors must persist until the user actually corrects the input (e.g. by typing). Automatically removing error styles after a timeout (like 2 seconds) while the error message is still visible leads to UI inconsistency and user confusion. Additionally, when clearing form errors, both visual cues (like borders) and semantic cues (`aria-invalid`) must be explicitly reset to ensure screen readers correctly reflect the new state.
**Action:** Always link form inputs to their error containers using `aria-errormessage` and `role="alert"`. Remove auto-hiding timeouts for validation errors and instead use an `input` event listener to clear `aria-invalid`, hide the error message, and remove error styling simultaneously when the user starts typing.
