## 2024-11-20 - Accessible Custom Button Groups and Form Validation
**Learning:** Custom button groups acting as radio selectors (like Mission Type and Difficulty) need to be explicitly managed for accessibility. Using `div`/`label` is less semantic than `fieldset`/`legend`. Also, using `role="group"` instead of `role="radiogroup"` preserves native button tab navigation but requires explicit `aria-pressed` management via JavaScript to reflect the active selection state. For form validation, automatically hiding errors via a timeout (e.g. 2000ms) leads to poor UX; errors and `aria-invalid` states should persist until the user explicitly corrects the input (e.g., via the `input` event).
**Action:** Always use `fieldset` and `legend` for grouped radio-like inputs. When using a custom UI built with buttons, add `role="group"` to the container and manage `aria-pressed` on the buttons with JS to sync with visual `.active` classes. Ensure form validation errors are cleared by user interaction, not timeouts, and remember to update the `aria-invalid` state and inline styles explicitly.
